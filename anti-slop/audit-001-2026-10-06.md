# Audit 001: Alur Mockup

Tanggal: 6 Oktober 2026
Mode: AFTER
Ruang lingkup: alur generate proposal/mockup, preview kandidat, dan build WordPress dari workspace.
Metode: inspeksi kode dan tes yang sudah ada. Tidak menjalankan aplikasi atau tes.

## Temuan

### 1. HIGH — Polling tidak berhenti setelah generate selesai (R-26)

`resources/views/pages/project-workspace.blade.php`: status `completed` dipetakan ke variabel `status = 'done'`, tetapi kondisi selesai memeriksa `data.status === 'done'`. Backend mengirim `completed`, sehingga halaman tidak reload ke proposal baru dan polling berlanjut; tombol Generate tetap disabled sampai halaman dimuat ulang manual.

### 2. HIGH — Demo kandidat lama menampilkan tautan yang berakhir 404 (R-26)

Workspace mendukung data proposal lama dengan membungkus `mockup` tunggal menjadi satu kandidat. `MockupPreviewController::candidate()` hanya mencari `mockup_candidates`, jadi tautan Open Live Demo yang muncul untuk data lama gagal dengan 404.

### 3. HIGH — Request generate berulang dapat menjalankan pipeline dan biaya provider secara paralel (R-27)

`WebsiteBuilderController::generateProposal()` selalu dispatch job baru. `PipelineCheckpointService::remember()` memeriksa checkpoint, menjalankan provider, lalu menyimpan hasil tanpa lock atomik. Jika request terkirim dua kali atau dari dua tab, kedua job dapat melewati pemeriksaan yang sama dan membuat panggilan AI/aset ganda.

### 4. HIGH — Build gagal dapat meninggalkan unduhan lama terlihat seperti hasil build terbaru (R-27)

`BundleController::build()` mempertahankan `ProjectBundle` berstatus `exported` yang sudah ada ketika build atau ekspor berikutnya gagal. Workspace masih dapat menampilkan tautan unduh ZIP itu, padahal pilihan mockup tersimpan sudah berubah dan ZIP berasal dari build sebelumnya.

### 5. MEDIUM — Opsi pertama tampak dipilih sebelum klien atau operator memilihnya (R-09)

Proposal baru menyimpan `selected_mockup_index = 0` sebagai nilai awal. Workspace memberi border aktif pada opsi itu, dan demo menampilkan badge “Dipilih”, meskipun aplikasi belum menerima pilihan klien. Ini memberi status yang tidak didukung data.

## Catatan alur pengguna saat ini

1. Operator membuka project dan menekan Generate Proposal.
2. Job menganalisis brief, membuat tiga blueprint desain, merender foto/screenshot, lalu menyimpan PDF serta data kandidat.
3. Operator mengirim PDF ke klien di luar aplikasi. Klien memilih opsi melalui komunikasi eksternal.
4. Operator dapat membuka demo kandidat di workspace, lalu menekan tombol build pada opsi yang dipilih klien.
5. Request build menyimpan kandidat yang ditekan, membuat tema WordPress, mengekspor ZIP, dan menampilkan unduhan.

Preview demo saat ini berada di balik autentikasi, jadi URL demo tidak dapat langsung dibagikan ke klien tanpa login. Proposal PDF tetap menjadi jalur berbagi eksternal yang didukung alur sekarang.

## Batas audit

Temuan visual seperti kontras, responsivitas hasil render, dan operasi keyboard belum diverifikasi di browser. Belum ada perubahan kode maupun tes yang dijalankan.
